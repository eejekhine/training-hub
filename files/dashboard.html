The AI layer, specced (15 Sep) — still Phase 6, built last
Home-LLM, not a from-scratch build. A Home Assistant component made exactly for this — plugs into your existing architecture as both the conversation agent (voice/chat) and inside automations (decision-making), so "assistant + automation" is one component, not two separate projects.
Local vs. hosted is no longer a hard fork. Home-LLM ships small purpose-built models (Llama 3.2 3B, Gemma 270M) light enough to run on Raspberry Pi-level hardware — so the spare desktop almost certainly runs it locally for free, whatever its specs turn out to be. Checking the specs (r4) still matters for whether it can also run a bigger general model for richer conversation.
Recommended setup: hybrid. Local model handles the bulk — device commands, simple automation calls — free, private, works offline. A cheap hosted model (GPT-4o-mini class, ~$0.15/$0.60 per million tokens as of Aug 2026) wired in only as a fallback for complex or free-form chat. At that pricing, even heavy personal use runs pennies to a couple of pounds a month — worth checking current rates again nearer the time.
Being honest about "learns patterns": a system that genuinely learns your habits with no rules is a much bigger, open-ended ML project than fits here — out of scope for now. What's realistic: standard Home Assistant automations built around your actual routine (night shift → climate/lighting by time of day, Xbox/PC wake), with Home-LLM layered on top to make case-by-case calls using live sensor data within those rules, plus handle the conversational side. That's genuinely "assistant + automation" without it becoming a research project.
Stays last in the build order — it needs Home Assistant live with real devices and entities exposed before there's anything for it to control. The difference now: Phase 6 isn't a placeholder anymore, it's a specced component ready to wire in when you get there.
